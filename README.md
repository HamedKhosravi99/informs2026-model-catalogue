# INFORMS 2026 DMS Data Challenge — model catalogue and code

Complete record of the modelling work for the INFORMS 2026 Data Mining Society
Data Challenge: every experiment we ran, how each was classified, what it scored,
and the code that produced all of it.

**This repository is private.** It contains no competition data. `DM_Train.csv`,
`DM_Test.csv`, `sample_submission.csv` and the organisers' PDFs are NDA-protected
and are excluded by `.gitignore`; the only PDFs here are our own report and
catalogue. Place the three competition CSVs in the repository root to run anything.

---

## The problem in one paragraph

Forecast an hourly county Outage Severity Index (OSI) through a two-wave March 2026
wind event across Indiana, Ohio, Pennsylvania and West Virginia. Each county has a
216-hour window; hours 0–71 are observed and outage variables are withheld
thereafter, so hours 73–215 must be predicted. Weather is given for all 216 hours,
making this a known-future-covariate problem where the horizon is twice the context.
Training and test counties are disjoint (239 / 63), so a test county's own outage
history is never available: this is **cross-sectional transfer**, not continuation
of a series. 42.4% of scored cells are exactly zero and the target has skew 8.8.

Scoring is RMSE computed **separately for each of four horizons** (t+1, 6, 24, 48 h),
with teams ranked within each horizon and the four ranks averaged. There is no
official single number; the mean of the four RMSEs used throughout is a reporting
summary.

## Headline result

| model | RMSE |
|---|---|
| all-zeros (the target's own RMS) | 0.01632 |
| decayed persistence | 0.01110 |
| best single model (A3x25) | 0.00862 |
| **submitted ensemble** | **0.00835** |

25% better than the strongest naive baseline; removes 73% of the target's squared
magnitude against 54% for persistence. All figures are five-fold county-holdout
cross-validation on the 239 training counties.

### How experiments are classified

An experiment is classified by the **contrast it was run to test**, not by the
properties of the model it produced. A shipped member may be a bi-GRU with a dual
objective and snapshot averaging; the run that admitted it changed exactly one of
those against a control. Classifying finished models instead is what makes most
ablation tables incoherent — "sequence architectures", "augmentation" and
"objective design" are not alternatives, they are different kinds of thing.

| code | family | runs |
|---|---|---|
| `F2` | Mechanism | 69 |
| `F1` | Signal | 47 |
| `F4` | Exposure | 32 |
| `F3` | Target | 27 |
| `F5` | Estimation | 23 |
| `F6` | Adaptation | 6 |
| `X` | Compound | 5 |
| `F7` | Combination | 4 |
| `P` | Protocol | 4 |
| `F8` | Uncertainty | 1 |

`F1` signal · `F2` mechanism · `F3` target · `F4` exposure · `F5` estimation ·
`F6` adaptation · `F7` combination · `F8` uncertainty · `P` protocol (choosing or
evaluating rather than predicting) · `X` compound (changed more than one stage;
retained but not used as single-family evidence).

Each row also records the **design axes** where the code determines them
unambiguously: the function class actually instantiated, the training objective,
the per-horizon scores, MAE, runtime, and whether the run reached the shipped
ensemble.

## The shipped model

    prediction = 0.5 * C[11 members] + 0.5 * A,  then x0.667 on hours >= 168

`C` combines members by **amplitude and shape separately** — the mean of their
per-county totals times the mean of their normalised trajectories. It is
parameter-free, equals the plain mean when members agree on timing, and preserves
peak height when they do not. `A` is a bi-GRU estimated 25 seeds x 4 snapshots
(100 networks), the best single model, carrying half the weight alone.

Eleven members span five function classes: bi-directional GRU (x2), GRU with
augmentation (x3), cross-county attention, patch transformer, gradient-boosted
trees, and three stock-flow state-space models. **The three worst models in the
set are the three most decorrelated and the hardest to remove.**

## What the record shows

Three findings the ledger supports, each measured rather than argued:

1. **A member's value is its error basis, not its score.** The stock-flow models
   score 0.0104–0.0115 alone, barely better than decayed persistence, and no
   substitute survived a replacement test.
2. **Improving a member can make the ensemble worse.** Snapshot-ensembling one
   member gave its best-ever solo score and made the blend significantly worse
   (P = 0.011). Re-running all ten remaining members at 25 seeds reproduced it:
   six improved alone, none was adopted on any fold, all ten together lost.
3. **Every selection procedure reversed under nesting** — greedy weights, NNLS,
   distillation, subset selection, per-column blend weights. The shipped model
   therefore contains no member chosen by cross-validation rank.

## Running the code

```bash
pip install -r requirements.txt          # pinned; Python 3.9
python3 make_submission.py               # rebuild the prediction file end-to-end
python3 canonical.py                     # regenerate every number quoted anywhere
python3 build_catalogue.py catalogue     # regenerate this catalogue
python3 family_ledger.py                 # recode the runs into families
```

| script | purpose |
|---|---|
| `make_submission.py` | trains every member on all 239 counties and writes the submission |
| `canonical.py` | recomputes all headline figures from cached out-of-fold predictions |
| `verify_submission.py` | 28 independent format and causality checks |
| `swap_check.py` | nested member-substitution test |
| `addone_sweep.py` | nested add-one sweep over every cached model |
| `rank_check.py` | applies the organisers' average-rank rule alongside our mean |
| `eval_sota.py`, `combo_rules.py`, `smearing.py`, `find_severe.py` | the analyses behind specific findings |

`src/ideas*.py` hold the model definitions, one module per sweep. `oof/` (cached
out-of-fold predictions) is git-ignored and regenerable with
`python3 run_all_ideas.py --only <ID>`.

## Reproducibility and compliance

Every seed is fixed and the pinned environment is CPU-only, so a clean clone
reproduces a byte-identical SHA-256. No outage-derived value from a timestamp
after hour 71 reaches any feature: masking happens before feature construction,
and overwriting every post-origin outage value with garbage changes predictions
by exactly 0.0. See [`REPRODUCE.md`](REPRODUCE.md) and [`SUBMISSION.md`](SUBMISSION.md).

`data_static/` contains committed external covariates (land cover, forest
inventory, terrain, utility infrastructure, sub-county weather). All are static,
public and outage-free. One member uses them; a package-only fallback costs
0.00004, measured.
